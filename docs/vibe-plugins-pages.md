# Vibe Plugins landing pages — how the system works

Every Vibe plugin gets a landing page at `626labs.dev/<plugin-id>/`, plus a
family index at `626labs.dev/plugins/`. The pages are **data-driven**: one
template + one content file + one render script. Change the design once,
regenerate all pages.

This is the same no-build, inline-CSS idiom as the rest of the hub (see
`render-hub.py`). No framework, no bundler.

## The three moving parts

| File | Role |
|---|---|
| `scripts/render-plugin-pages.py` | The generator. Holds the shared HTML/CSS template + per-section renderers. Reads the data file, writes `<id>/index.html` for each plugin and `plugins/index.html`. |
| `content/plugin-pages.json` | The content. One entry per plugin (hero, sections, install, terminal) + a shared `family` list. |
| `assets/brand/plugins/<id>-*.png` | The art. Generated by `scripts/export-plugin-icons.py` — a square, two banners, and a transparent glyph icon per plugin. |

## To add a new plugin page

1. **Add the plugin to the icon generator.** In `scripts/export-plugin-icons.py`:
   - Write a `glyph_<name>()` function (line-art, 200×200, transparent, uses the plugin's `primary`/`secondary` accent). Register it in the `GLYPHS` dict.
   - Add an entry to the `PLUGINS` list: `id`, `name` (UPPERCASE wordmark), `tagline`, `glyph` (the GLYPHS key), `primary`, `secondary`.
   - Run `python scripts/export-plugin-icons.py`. This regenerates **all** plugins' PNGs (PNG re-encode is non-deterministic), so stage only your new plugin's files:
     `git add assets/brand/plugins/<id>-*.png` and `git restore` the rest.

2. **Add content.** In `content/plugin-pages.json`:
   - Add the plugin to the top-level `family` array (`id`, `name`, `role`, `href: "/<id>/"`, `beat` optional — raw HTML, shown on the family index).
   - Add a `plugins.<id>` entry. Copy an existing one as the shape. Source the content from the plugin's own repo — **no fabrication**; command names, counts, and descriptions must be accurate.

3. **Generate.** `python scripts/render-plugin-pages.py` writes `<id>/index.html` and refreshes `plugins/index.html` and the family section on every other page.

4. **Verify + commit.** Open the page locally (`python -m http.server` from the repo root, visit `/<id>/`). Check it renders, links resolve, install copy works. Commit the new `<id>/index.html`, the data, and the icons.

## The data model (`plugins.<id>`)

```jsonc
{
  "name": "vibe-foo",                       // wordmark (lowercase, shown in nav + family)
  "metaTitle": "...", "ogTitle": "...",     // <title> and og:title
  "metaDescription": "...",                 // SEO + og/twitter description
  "ogImage": "/assets/brand/plugins/vibe-foo-banner-1280x640.png",
  "eyebrow": "626Labs · Claude Code plugin",
  "h1": "Headline.",
  "subhead": "1-2 sentences. Raw HTML allowed (&mdash; &rarr; <strong>).",
  "heroMeta": ["v1.0.0", "N commands", "MIT"],
  "ctas": { "primary": {"label": "Install plugin"},
            "secondary": {"label": "View on GitHub", "href": "..."} },   // secondary optional
  "terminal": {                              // optional — omit for a centered solo hero
    "label": "vibe-foo ~",
    "lines": ["<span class=\"prompt\">$</span> <span class=\"cmd\">/cmd</span>", "..."]
  },
  "sections": [
    { "type": "cards", "eyebrow": "01 · ...", "heading": "...", "lead": "...",
      "cols": 3,                             // optional: 3-up grid; default 2
      "cards": [ {"command": "/x:y", "title": "...", "desc": "...", "reach": "..."} ],
      "mini": {                              // optional sub-grid (e.g. sidecars)
        "heading": "...", "hint": "...",
        "items": [ {"name": ":foo", "desc": "..."} ] } },
    { "type": "prose", "eyebrow": "02 · ...", "heading": "...",
      "paragraphs": ["raw HTML ok"], "callout": "plain text, optional" }
  ],
  "install": {
    "stable": "line1\nline2", "stableBlurb": "...",
    "canary": "line1\nline2", "canaryBlurb": "...",   // canary optional → single-card install
    "note": "optional footnote"
  }
}
```

### Escaping rules (important)

The generator renders some fields as **raw HTML** (so you can use `&mdash;`,
`&rarr;`, `<strong>`, `<em>`) and others **escaped** (plain text only — entities
would double-escape):

- **Raw HTML:** `subhead`, card `desc`, card `reach`, prose `paragraphs`, `terminal.lines`, `family[].beat`.
- **Escaped (plain text):** `name`, `eyebrow`, all headings, card `title`, card `command`, `callout`, `mini.name`.

The top-level `thesis` object (rendered by `render_thesis` onto `/plugins/#thesis`)
follows the same split:

- **Raw HTML:** `thesis.lead`, `thesis.quote`, `thesis.paragraphs[]`, `thesis.artifacts[].blurb`.
- **Escaped (plain text):** `thesis.eyebrow`, `thesis.headline`, `thesis.cta.label`,
  `thesis.cta.href`, `thesis.artifacts[].eyebrow`, `thesis.artifacts[].title`,
  `thesis.artifacts[].links[].label`, `thesis.artifacts[].links[].href`.

## Terminal demo markup

Lines are raw HTML rendered inside `<div>…</div>` in a monospace block. Span classes:

| class | use |
|---|---|
| `prompt` | the `$` or `&gt;` prompt glyph (cyan) |
| `cmd` | the typed command (white) |
| `agent` | agent label like `[Ptolemy]` (cyan) |
| `path` | file paths, package names (pale cyan) |
| `key` | emphasis values (magenta) |
| `ok` | success markers (green) |
| `muted` | de-emphasized notes |
| `term-cursor` | blinking cursor (put on the last line) |

Keep demos accurate to the plugin's real commands/output. Use `&nbsp;` for blank lines.

## Drift check (CI)

`python scripts/render-plugin-pages.py --check` exits 1 if any page is stale
relative to the data + template. Run it after editing the data; wire it into CI
the same way `render-hub.py --check` is used.

## Deploy

Pages live on `main` and deploy via GitHub Pages on push. The hub's
`link-check.yml` validates links on any `**/*.html` change. The main hub cards
link to each page via the `productPage` field in `content/site.json`.
