01 · What it does

The predictable fingerprint of an AI-built app — found and fixed.

When an LLM builds your app, it optimizes for a working demo. vibe-sec knows the gap between that and a deployable system, and works through it systematically. Commands below are the design — the plugin is pre-release; the CLI scanner ships today.

/vibe-sec:scan

Full security scan.

Classifies app type and deployment context, then runs the three-layer audit — hygiene (secrets, headers, CORS), architecture (auth, validation, authorization), and dependency CVEs. Findings prioritized by tier, not an abstract ideal.

/vibe-sec:fix

Generate and apply fixes.

Automated for high-confidence hygiene issues (gitignore entries, security headers, removing hardcoded secrets); guided templates for architectural issues.

/vibe-sec:audit

Deep dependency audit.

CVE cross-reference against direct and transitive deps, lock-file integrity, pinned-vs-floating audit, and typosquat detection.

/vibe-sec:threat-model

Guided threat modeling.

STRIDE-style analysis from your app's actual surface area. Outputs a document vibe-doc can render.

/vibe-sec:check

CI pass/fail gate.

CI-safe exit codes against your app's security tier. Drops into a GitHub Action without configuration.

/vibe-sec:status

Security posture summary.

Last scan, open findings by severity, fixes applied vs deferred, and threat-model status.

02 · The design

Three layers, one classifier, fixes you can ship.

vibe-sec separates security into three layers that compound. Hygiene is fully automatable: secrets out of source, headers added, CORS locked down. Architecture requires understanding how the app is built — does the auth actually protect the routes it claims to? Threat modeling asks what the realistic attack vectors are given this app's deployment context, and proposes a model for you to validate.

The classifier is what keeps it from being generic. The same finding — say, missing rate limiting — might be critical for a payment API and informational for a personal static site. vibe-sec classifies your app first (prototype → regulated enterprise); the tier sets the bar, not a one-size-fits-all checklist.

Goal: from "I have a vibe-coded app" to "I know what's insecure" in under 2 minutes.
